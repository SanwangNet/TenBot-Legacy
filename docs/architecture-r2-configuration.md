# R2.1 configuration

`createConfigurationService` in `packages/config` reads existing schema with environment variables taking precedence over `.env`, both ahead of Web settings and schema defaults. Web values are written to `data/web-config.json`, never `.env`. Only allowlisted non-secret public fields can be persisted. Environment and `.env` are reported as `environment`; public snapshots contain redacted values, source labels and the Web document revision. Revision-checked updates are serialized per service instance and use atomic file replacement. Environment edits are reloaded by the existing Runtime watcher; the revision describes the persisted Web document, not process-wide environment changes. Multi-process writers do not have cross-process compare-and-swap guarantees.

`getAppConfig` is an internal-only interface and contains credentials needed by the existing Runtime. It must never be returned from a public endpoint or logged. `getSnapshot` is safe for authenticated management APIs and exposes no credential values. The existing Runtime consumes this service and publishes source metadata; the legacy ConfigStore remains for existing direct callers during migration. An environment override means a saved Web value is retained but not active.

R2.2 should build authenticated initialization on the revision-checked update boundary, define secure credential storage and redacted secret status, support reliable transactional multi-process concurrency if needed, and explicitly handle changes that require a Runtime restart. Do not expose anonymous writes.
